# BLE Beacon 기반 Quick LBS 시스템 — 개발 명세


## 1. 개요

AGV에 손대지 않고 BLE Beacon + 스마트폰 공기계로 AGV 위치를 추정한다.
근접(Proximity)과 지문(Fingerprinting) 두 방식을 구현하고, 모든 파라미터는
어드민에서 런타임 조정한다. **어드민(설정·시각화·실험관리)이 핵심 산출물.**

어드민은 **실험 모드와 운영 모드 둘 다** 지원한다. 실험 모드는 PoC·튜닝용(파라미터를
바꿔가며 측정·비교·기록), 운영 모드는 현장 배포 후 상시 관제·관리용. 공통 기반(레이아웃·
비콘·알고리즘 설정, 실시간 시각화)을 공유하되, 운영 모드는 안정 동작과 상시 모니터링,
실험 모드는 변수 조작과 결과 기록에 중점을 둔다.

### 1.1 구성
```
[BLE Beacon 다수]  ))BLE((  [공기계 (AGV 탑재)]  ──Wi-Fi/MQTT──>  [판독 서버]  <──>  [어드민]
   (벽·기둥 고정)             (RSSI 측정·발행)                    (위치 추정)      (제어·시각화)
```

### 1.2 역할 분담
- **공기계(엣지)**: BLE 스캔 → RSSI + 타임스탬프 수집 → 경량 집계(옵션) → MQTT 발행. **위치 계산 안 함.**
- **서버**: 위치 판정. 모든 알고리즘 파라미터를 어드민에서 주입받아 구동.
- **어드민**: 레이아웃 편집, 설정 제어, 실시간 시각화, 실험 결과 관리.

### 1.3 전제
- AGV는 고정 경로를 한 방향 주행 → 비콘 통과 순서 고정(경로 순서 제약에 사용).
- 측위에 AP 불필요, 결과 전송에만 Wi-Fi 사용.
- 비콘 출력·광고 주기는 설정 가능(범위도 어드민에서 관리).
- **xMS 인터락 연동은 범위 외**(위치 추정 결과 산출까지).



## 2. RSSI 처리 전제
- RSSI: dBm, 음수. 0에 가까울수록 강함. 로그 척도(10dB=전력 10배).
- 칩 제조사·기종마다 ±10dBm 편차 → **기종별 offset 보정 필요**.
- 금속 반사·차폐·간섭으로 정지 상태에서도 ±수 dBm 변동 → **평활화 필요**.
- 경로손실 거리환산은 오차가 커서 사용 안 함 → 근접·지문 방식 채택, 삼변측량 제외.



## 3. 목표 정밀도
- **겹침 구간 위치 오차: 목표 ≤ 30cm, 허용 상한 ≤ 50cm (1σ).**
- 평가 지표: ① 경로 방향 평균 오차(정지·주행 각각) ② 구간 경계 오판(진입/이탈 오인) 빈도.
- 금속 환경 BLE 단독으로 30cm 달성 가능 여부가 본 PoC의 핵심 검증 항목.



## 4. 측위 알고리즘 (서버 구현)

### 4.1 근접(Proximity)
가장 센 비콘 기준 판정 + 아래 보강. 각 파라미터는 어드민 주입.
- 상위 N개 무게중심 보간: 상위 N개 세기를 가중치로 위치 보간(N 가변).
- 평활화: 이동평균 / 중앙값 / EMA 중 선택, 윈도 크기 가변.
- 이력(hysteresis): 전환 임계값으로 깜빡임 억제.
- 경로 순서 제약: on/off. 통과 순서 이탈값 제거.

### 4.2 지문(Fingerprinting)
- 수집 모드: 경로 주행하며 지점별 RSSI 패턴을 맵으로 저장.
- 운영 모드: 현재 패턴을 맵과 대조해 최근접 지점 판정.

### 4.3 fail-safe
- 최근 수신 후 타임아웃(가변) 초과 또는 최소 수신 개수 미달 시
  해당 구간을 "점유 중"으로 처리.



## 5. 컴포넌트별 요구사항

### 5.1 공기계 앱 (Android)
- BLE 스캔(LowLatency, 포그라운드 서비스, 절전 예외).
- 비콘별 식별자(UUID/Major/Minor 또는 MAC) + RSSI + 타임스탬프 수집.
- 전송 주기 내 동일 비콘 다중 수신 시 경량 집계(옵션, 어드민 설정).
- MQTT 발행(§7.1). Wi-Fi 단절 시 단기 버퍼 후 재전송.
- 측정 모드: RSSI·타임스탬프 CSV 로컬 저장(기종 선별·튜닝).
- 기종 식별자 전송.

### 5.2 판독 서버
- MQTT 구독, 다수 공기계 RSSI 수집.
- 비콘 offset + 기종 offset 적용(어드민 주입).
- §4 알고리즘 구동. **모든 파라미터 런타임 반영(재시작 없이).**
- 추정 위치·원시 로그 저장, 어드민 시각화용 스트림 제공.
- 지문 맵 수집/대조.

### 5.3 어드민 (핵심)
설계 기조: **코드 수정 없이 설정을 바꾸고, 결과를 보고, 기록한다.**

**모드**: 실험 모드(PoC·튜닝) / 운영 모드(현장 상시 관제). (a)~(c)는 공통,
(d) 실험·기종 관리는 실험 모드 중심, 운영 모드는 (c) 시각화 + 알람·상태 모니터링 중심.

**(a) 레이아웃 편집기**
- 격자 크기 사용자 지정(50cm / 1m / 2m 등 임의값).
- 도면 이미지 배경 위에 격자 오버레이.
- 격자 위에 비콘 배치(드래그 이동). 배치 패턴 자유(격자/1열/지그재그).
- AGV 경로와 통과 순서 등록. 겹침 구간 지정.

**(b) 설정 제어**
- 비콘별: 식별자, 좌표, 송신 출력, 광고 주기, 보정 offset. 출력·주기 설정 범위 관리.
  광고 주기는 짧을수록 유리하나 제품 설정 하한 확인 필요 → 주기별 측위 결과를 비교·기록.
- 알고리즘: 방식(근접/지문/병행), 무게중심 N, 가중 방식, 평활화 방식·윈도, 이력 임계,
  경로 순서 제약 on/off, 전환 임계, 갱신 타임아웃, 최소 수신 개수.
- 변경 즉시 서버 반영.

**(c) 실시간 시각화**
- 도면·격자 위 추정 위치(AGV 마커) 및 궤적.
- 비콘별 RSSI 실시간 히트맵/바.
- 상위 N개 무게중심 기여도.
- 애매 구간(비콘 간 세기 동률 구간) 색 표시.
- 원시 RSSI vs 평활화 값 비교 그래프.

**(d) 기종·실험 관리**
- **다수 공기계 기종 동시 테스트·비교 관리**: 여러 대를 동시에 등록·측정하고,
  기종별 지표(초당 RSSI 갱신 횟수, RSSI 변동폭, offset, 측위 오차)를 나란히 비교.
  어떤 기종을 어느 조건에서 썼을 때 결과가 어땠는지 이력으로 조회. A/B(이상) 비교 뷰.
- 실험 세션 저장: (레이아웃 + 비콘 설정 + 알고리즘 파라미터 + 기종) 조합 단위.
- 세션별 측위 오차·안정성 지표 기록·비교. 원시 로그/CSV 내보내기. 지문 맵 관리.

**(e) 운영 모드 (현장 배포용)**
- 상시 위치 관제 화면(마커·궤적·구간 점유 상태).
- 비콘·공기계 상태 모니터링(신호 끊김, 배터리, 스캔 정상 여부)과 알람.
- 확정된 설정(검증된 파라미터 세트)을 적용·고정, 오조작 방지(설정 잠금).



## 6. 데이터 규격 (초안)

### 6.1 공기계 → 서버 (MQTT)
```json
{
  "phone_id": "agv-01",
  "device_model": "galaxy-sXX",
  "ts": 1760900000123,
  "beacons": [
    {"id": "uuid-major-minor 또는 MAC", "rssi": -62, "tx": -59},
    {"id": "...", "rssi": -71, "tx": -59}
  ]
}
```
rssi는 원본(가공 없음). 보정·평활화·판정은 서버.

### 6.2 레이아웃·비콘 (어드민 ↔ 서버)
```
layout: { grid_size_cm, background_img, path(순서), overlap_zones }
beacon: { id, x, y, tx_power, adv_interval, offset }
```

### 6.3 실험 세션
```
session: { layout_id, beacon_set, algo_params, device_model, metrics, log_ref, created_at }
```



## 7. 비기능 요구사항
- 실시간성: 전송·판정 지연이 AGV 이동 대비 위치 갱신에 지장 없을 것.
- 안정성: 공기계 장시간 스캔 유지, Wi-Fi 단절 복원, 서버 장애 시 안전 측 신호.
- 시간 동기: 공기계 간 타임스탬프 기준 통일(서버 수신 시각 또는 NTP).
- 대역 간섭: BLE 스캔(2.4GHz)과 Wi-Fi 전송 분리(가능 시 5GHz 업로드).
- 조정성: 핵심 변수 전부 어드민에서 재시작 없이 변경.



## 8. 검증 (성공 기준)
1. 기종 선별: 여러 후보 기종을 동시 등록·측정, 초당 RSSI 갱신 횟수·변동폭·측위 오차 비교 → 합격 기종(어드민 기록).
2. 출력 튜닝: 출력 단계별로 낮춰 "한 지점에서 1~2개만 또렷하게 잡히는" 지점 탐색.
3. 주기 튜닝: 광고 주기를 설정 하한까지 낮춰가며 주기별 측위 정밀도·안정성 비교(짧을수록 유리하나 하한 확인).
4. 근접 검증: 배치·파라미터를 어드민에서 바꿔가며 떨림·역주행·튐 측정.
5. 애매 구간: 두 비콘 중앙에서 RSSI 수십 초 기록 → "신호 차이 vs 노이즈 변동폭" 비율로 깜빡임 폭 정량화.
6. 지문 검증: 맵 생성 후 재주행 대조 정확도 → 근접 방식과 비교.
- **성공 기준: 오차 ≤ 30cm 목표 / ≤ 50cm 허용(1σ) 안정 달성, 구간 경계 오판 허용 수준 이하,
  달성 조합을 실험 기록으로 재현 가능.**



## 9. 리스크
| 리스크 | 대응 |
|---|---|
| 기종별 스캔율·RSSI 편차 | 어드민 기종 프로파일·비교, 사전 선별 |
| 금속 환경 RSSI 변동 | 평활화·무게중심·지문 병행, 파라미터 튜닝 |
| 비콘 중앙부 신호 동률 | 무게중심 + 경로 순서 제약 |
| Wi-Fi 단절 | 단기 버퍼 + 서버 타임아웃 점유 처리 |
| 라인 배치 변경 | 어드민 재캘리브레이션·레이아웃 재편집 |
| Android 백그라운드 스캔 제약 | 포그라운드 서비스·절전 예외 |
| 30cm 미달 가능성 | 지문·배치 조밀화·알고리즘 조정으로 한계 탐색, 미달 시 한계치 명확화 |



## 10. 장비 (PoC)
- 비콘: 현승 B-Fon E7(출력 -20~+4dBm, iBeacon, BLE 5.0) 다수.
- 공기계: 사내 보유분, 기종 미확정 → 어드민에서 비교·확정.
- 서버·어드민: 사내 서버.



## 11. 확정·미결
- 어드민 용도: **확정** — 실험 모드 + 운영 모드 둘 다 지원(현장 운영 포함).
- 공기계 기종: **미확정, 테스트 대상** — 여러 기종 동시 테스트·비교를 어드민에서 관리.
- 비콘 광고 주기: **설정 가능 전제, 측정 대상** — 실제 하한은 제품 확인, 주기별 결과는 어드민에서 비교.
